Security

This build is a client-side workspace. Passwords are stored as SHA-256 hashes in this browser only. That is not the same as a server login. Host privately. Do not put this file on a public site.

Change my password

New passwords need at least 8 characters with a letter and a number. The change is logged and requires a second confirmation.

Email / login alert

There is no hidden mail server in this HTML file. A JC login creates a local security notice. If you paste a HTTPS webhook URL, the app will POST the notice there. If the POST fails, you will see that it failed — it will never pretend the email was sent.

Additional security password

Used as the second factor for email and restore actions. Initial value is the team default. It is never displayed.

Backup / restore

Only JC may export or restore. Filenames include date, time and who generated the file. Schema version 9 travels with the file so later builds can migrate it.

Protected mode

Courtesy lock: copy/cut/context-menu on the desk is blocked while locked. Anyone who can view page source can still read this HTML. Real protection requires a private host and a server login.

About / limitations

  • v8.4 keeps the FS engine (universal upload, geometry OCR, P&C, draft signatures, partner-learned rules) and adds engagements, custom roles, login history, job reassign, schema-9 backups, and stricter alignment/grammar desk checks. v8.4 shows a cast log (agree and differ), checks cash and retained-earnings rolls, and pastes that log in front of the AI so an agreed total is not raised again.
  • All users, jobs, notices and logs live in this browser (localStorage + IndexedDB). Clearing site data wipes them unless you hold a JSON backup.
  • Role checks run in the page. They stop accidental misuse; they are not a server ACL.
